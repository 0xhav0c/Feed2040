Critical OpenSSH flaw allows unauthenticated remote code execution on glibc systems

Summary by AI
  • Race condition in sshd's SIGALRM handler (CVE-2026-6387) enables root RCE without authentication.
  • Affects OpenSSH 8.5p1 – 9.7p1 on glibc Linux; OpenBSD is not exploitable.
  • Upgrade to 9.8p1, or set LoginGraceTime 0 as a temporary mitigation.

Researchers disclosed a signal-handler race condition in OpenSSH's server that can let an unauthenticated attacker execute arbitrary code as root on Linux systems using glibc. The flaw is a regression of a bug fixed in 2006 and was reintroduced in October 2020.

Exploitation is not trivial: it takes on average around 10,000 attempts to win the race, which translates to several hours against a default configuration. Still, the researchers warn that the attack is reliable enough to be practical at scale.

Distributions including Debian, Ubuntu and Fedora shipped fixed packages within hours of disclosure. Administrators who cannot patch immediately can set LoginGraceTime to 0, at the cost of making sshd easier to exhaust with idle connections.
